# 릴스 카드뉴스 대본 만들기

주제가 무엇이든 같은 포맷과 같은 말투로 대본을 만든다. 주제별 내용은 매번 새로 받고, 계정 정보는 아래 "계정 프로필"을 따른다.

## 작업 순서
1. 주제, 핵심 메시지 한 줄, 대상(누구에게 도움이 되는가)을 파악한다.
2. 주제 유형을 고른다(아래 "장면 구성 패턴").
3. 사실 확인이 필요한 주제(정책, 금액, 날짜, 법규, 가격, 통계, 제품 사양)는 웹 검색으로 확인한다.
   - 공식 출처 우선, 한 곳에서만 나온 내용은 "미확인"으로 표시하고 영상에서는 뺀다.
   - 서로 다른 제도·제품·기관을 섞지 않는다. 출처가 엇갈리면 영상에서 뺀다.
   - 연도와 시점 상태(공고 전 / 진행 중 / 종료)를 먼저 판단해 각도를 정한다.
4. JSON 포맷으로 대본을 만든다.
5. `verify_before_post`로 게시 전에 사람이 확인할 항목을 낸다.

## 장면 구성 패턴
- 정보·혜택형: 후킹 → 핵심 조건 3~4개 → 신청·확인 방법 → CTA
- 팁 모음형: 후킹 → 팁 3~5개(장면당 하나) → 한 줄 정리 → CTA
- 비교형: 후킹 → A 특징 → B 특징 → 어떤 사람에게 맞는지 → CTA
- 방법·절차형: 후킹 → 단계별 한 장면씩 → 자주 하는 실수 → CTA
- 경험담형: 후킹(결과 먼저) → 상황 → 한 일 → 결과·배운 점 → CTA

## 대본 JSON 포맷
- `id`, `mode`: "card_news"
- `style`: "photo"(사진·영상 배경, 모든 장면 가운데 정렬) 또는 생략(네이비 카드)
- `backgroundSrc`: 전체 배경 파일 이름(public/ 안 이미지·영상). 비우면 기본 도시 일러스트
- `bgQuery`(선택): 전체 배경용 영어 검색어. `npm run backgrounds`가 무료 사진(Pexels)을 받아와 채운다
- `hookBg`, `ctaBg`(선택): 첫 화면·마지막 화면 배경 파일
- `hookLabel`(선택), `hook`: 첫 화면(3.5초)
- `scenes[]`: 5~7개, 장면당 4~5초. 장면 종류(`type`)는 3가지
  - `text`(기본): `{ t, label?, text, bg?, bgQuery? }`
  - `cards`(요약 카드): `{ t, type:"cards", label?, cards:[{label, value, sub?}], text?, ... }` 카드 2~4개. 핵심 수치·조건 요약에 쓴다
  - `table`(표): `{ t, type:"table", label?, table:{head:[...], rows:[[...]]}, ... }` 행 1~5줄, 비교·조건 정리에 쓴다
  - 모든 장면에 `bg`(public/ 안 이미지·영상 파일 이름) 또는 `bgQuery`(영어 검색어)를 줄 수 있다. 둘 다 없으면 전체 배경이 유지된다
- `ctaLabel`(선택), `cta`: 마지막 화면
- `accentColor`: 포인트 컬러(기본 #FF8A1F)
- `status`: "pending"(확정 전) 또는 "confirmed". confirmed가 아니면 `disclaimer_overlay` 문구가 영상 하단에 자동 표시된다
- `disclaimer_overlay`, `caption`, `hashtags`, `sources`, `verify_before_post`

## 글쓰기 규칙
- 말투는 "~해요/~예요" 체. 말 걸듯이 친근하게, 반말과 과한 감탄은 쓰지 않는다.
- 첫 화면은 결과나 궁금증이 바로 보이게 쓴다. 한 줄 짧게, 최대 2줄.
- 한 장면에 하나의 메시지, 최대 3~4줄. 줄바꿈은 `\n`.
- 라벨은 글만 봐서 맥락이 안 잡힐 때만 넣고, 문구만으로 충분하면 뺀다.
- `[[ ]]`로 핵심 숫자·단어만 포인트 컬러로 강조한다. 전체에서 2~3곳 이내.
- 캡션은 계정 시점의 한 줄 + 기준 시점 문구(해당할 때).
- 이모지는 첫 화면과 캡션에서만 가볍게 쓴다.

## 배경 규칙
- 사용자가 준 영상·이미지가 있으면 public/에 넣고 `backgroundSrc` 또는 장면별 `bg`에 파일 이름을 적는다. 이것이 항상 우선이다.
- 없으면 주제와 관련된 영어 `bgQuery`를 장면마다 적는다(예: "apartment night city", "calendar planner desk"). 사람 얼굴이 크게 나오는 사진, 로고·상표가 보이는 사진은 피한다.
- 사진 키가 없는 환경에서는 기본 일러스트가 깔린다. 이때도 렌더링은 정상이다.
- 배경 위에는 어두운 오버레이가 자동으로 깔려 글자가 읽힌다. 배경은 글보다 눈에 띄지 않게 고른다.

## 카드·표 사용 규칙
- 숫자나 조건이 3개 이상 나열될 때만 카드·표를 쓴다. 한 문장으로 되는 내용은 `text`로 둔다.
- 영상 전체에서 카드·표는 1~2장면 이내. 연속으로 두 장면에 쓰지 않는다.
- 카드 `value`는 짧게(8~10자 이내), 표 칸은 한 줄에 들어가게 쓴다.
- 확인되지 않은 수치(미확인·출처 엇갈림)는 카드·표에 넣지 않는다.

## 연출 규칙
- 글자는 줄 단위로 위로 살짝 올라오며 선명해지는 효과로 차례로 나타난다(템플릿이 자동 처리). 별도 지정은 필요 없다.
- 장면 끝에서 살짝 사라지고, 장면 배경은 아주 천천히 확대된다. 더 화려한 효과는 쓰지 않는다.
- 큰 글자는 히피체, 라벨 칩·카드 설명·표는 고딕체(Noto Sans KR)다.

## 줄바꿈 규칙
- 줄바꿈은 항상 단어(어절) 단위로 한다. 단어 중간에서 끊지 않는다.
- `\n`은 의미가 끊기는 자리(주어·서술어, 조사 앞이 아니라 어절 사이)에 넣는다. 한 줄은 공백 포함 12자 안팎으로 쓴다.
- 템플릿은 `word-break: keep-all`로 어절 단위로 줄을 나누고 줄 길이를 균형 있게 맞춘다.

## 면책 규칙
- 시점이 바뀔 수 있는 정보(정책, 가격, 일정, 조건)는 `disclaimer_overlay`("○○년 기준 · 변경될 수 있어요")를 넣고 `status`를 "pending"으로 둔다.
- 공식 출처로 확인한 뒤에만 사람이 `status`를 "confirmed"로 바꾼다.
- 시간이 지나도 변하지 않는 팁은 `disclaimer_overlay`를 생략한다.

## 게시 전 검수 체크리스트
- 수치, 날짜, 조건이 공식 출처와 일치하는가
- 기관·제품·제도 이름이 맞는가
- 기준 연도와 시점 표기가 맞는가
- 저작권이 있는 이미지·음원·폰트를 쓰지 않았는가
- 과장된 표현, 보장하는 말투("무조건", "100%")를 쓰지 않았는가

## 레퍼런스 활용 규칙
- 레퍼런스(남의 릴스·쇼츠·글)는 주제 발굴과 구성 패턴 분석용으로만 쓴다.
- 문구, 장면 순서, 영상, 이미지를 그대로 따라 하지 않는다. 우리 계정 시점으로 새로 쓴다.
- 레퍼런스에서 가져온 수치·사실은 반드시 공식 출처로 다시 확인한다.

## 계정 프로필 (계정 바뀌면 이 부분만 수정)
- 정체성: 부산 출신으로 서울에 상경해 사는 2030 갓생러
- 채널 주제: 재테크, 자취 꿀팁, 청년 혜택
- 해시태그 기본: #자취꿀팁 #2030재테크 #상경러 (주제에 맞게 추가)
- 캡션 마무리 톤: 같은 상경러 입장의 한마디
